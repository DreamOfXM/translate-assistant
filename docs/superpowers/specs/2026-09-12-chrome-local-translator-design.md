# Chrome 本地翻译插件设计方案

## 目标

开发一个免费的 Chrome/Chromium 扩展，让用户在当前网页内手动翻译外语文本，并用自己的母语编写回复，再将确认后的译文填入网页输入框。核心翻译完全在浏览器本地执行，不调用云端 API、不要求本地后台服务、不自动发布内容。

## 用户场景

1. 用户在网页中选中外语文本，手动触发“翻译为中文”，在当前页面显示结果。
2. 用户点击评论框旁的翻译按钮，在插件面板中用中文输入，手动触发翻译为目标语言。
3. 用户查看原文和译文，确认后将译文填回原网页输入框，再由网页原生发送流程负责发布。
4. 用户在语言包管理页面选择语言方向，下载、删除或查看已缓存语言包。

## 范围

### 第一版包含

- Chrome Manifest V3 扩展。
- Content Script：识别可编辑元素、选择文本、注入非侵入式操作入口。
- Background Service Worker：处理右键菜单、消息路由和语言包状态。
- Extension UI：Popup 或 Side Panel、翻译面板、语言包管理。
- 手动选中文本翻译。
- 手动触发中文到目标语言的回复翻译。
- 支持 `textarea`、文本输入框和 `contenteditable`。
- 用户确认后填回译文，不自动点击发送。
- WebAssembly 翻译运行时和按语言方向下载、缓存的模型包。
- 离线翻译：已安装语言包后不需要网络。

### 第一版不包含

- 自动翻译整页或自动修改网页文本。
- 自动发布评论。
- 云端模型、API Key 或账户系统。
- 针对 Reddit、TikTok、YouTube、X 等网站的专用适配。
- 图片 OCR、音频翻译和视频字幕翻译。

## 技术架构

```text
网页
  └─ Content Script
       ├─ 选择文本与输入框识别
       ├─ 页面内结果浮层
       └─ 向 Service Worker 请求翻译

Extension UI
  ├─ 回复翻译面板
  └─ 语言包管理

Background Service Worker
  ├─ 消息校验与路由
  ├─ 右键菜单
  ├─ 当前标签页语言上下文
  └─ chrome.storage 状态管理

WASM Translation Runtime
  ├─ 语言检测
  ├─ 翻译管线
  └─ 已下载语言方向模型包
```

翻译运行时优先采用可在浏览器内运行的开源 WASM 方案；候选实现包括 Bergamot/Firefox Translations 的可复用组件或兼容的 Marian/NLLB WebAssembly 运行时。选型必须满足 Chrome 扩展 CSP、模型包许可证、离线运行和可接受的包体积要求。不能在未验证许可证和浏览器兼容性前捆绑模型文件。

## 数据流

### 选中文本翻译

1. Content Script 读取用户当前选区文本，不读取无关页面内容。
2. 用户点击右键菜单或浮层按钮。
3. Service Worker 确认源语言、目标语言和对应语言包状态。
4. 若语言包未安装，UI 提示用户进入语言包管理并下载。
5. WASM 运行时在本机执行翻译。
6. 结果返回 Content Script，在选区附近显示可关闭结果卡片。

### 回复翻译

1. Content Script 识别当前获得焦点的 `textarea`、`input` 或 `contenteditable`。
2. 用户点击注入的翻译入口，打开面板并保留目标输入框引用。
3. 用户在面板输入母语文本，点击“翻译”。
4. 插件使用用户选择的目标语言；自动检测仅作为建议，不作为强制决策。
5. 显示原文、译文和“重新翻译”“填入输入框”操作。
6. 只有用户点击“填入输入框”后，插件才通过原生事件更新网页输入框。
7. 不调用提交、发送、回车或点击发布按钮。

## 语言包管理

- 语言包按“源语言 → 目标语言”作为独立下载单元。
- 用户可以搜索语言、查看大小、下载、暂停、删除和查看状态。
- 删除语言包不影响插件核心功能和其他方向。
- 下载前显示预计大小和所需存储空间。
- 下载完成后校验版本和完整性，再写入 Cache Storage 或 IndexedDB。
- 语言包元数据包含语言代码、方向、版本、大小、校验值和许可证信息。
- 首批界面不预设固定语言数量，目录支持后续扩展；默认提供中文、英语、日语等常用方向作为推荐项。

## 权限和隐私

Manifest V3 只申请完成功能所需的最小权限。初步权限为 `storage`、`contextMenus`、`scripting`，页面注入采用用户触发时机。扩展不上传网页文本、评论草稿或翻译结果；评论草稿默认仅保存在当前内存，不写入持久存储。语言包下载仅访问明确的模型资源地址，并在 UI 显示来源和许可证。

## 错误处理

- 未安装语言包：提示缺少方向并提供下载入口。
- 模型加载失败：显示重试和删除后重新下载选项。
- 文本过长：提示分段翻译，不静默截断。
- 无法识别输入框：提供复制译文按钮，不修改页面。
- 网页使用受限编辑器：优先使用标准 DOM 事件，失败时保留译文供复制。
- 页面卸载或输入框失效：阻止填入并要求用户重新选择输入框。
- 翻译异常：保留原文、显示明确错误，不丢失草稿。

## 验收标准

1. 不配置 API、不运行本地服务时，已安装语言包仍能完成离线翻译。
2. 用户选中文本并手动触发后，当前网页显示译文，不打开新页面。
3. 用户能在通用 `textarea`、`input` 和 `contenteditable` 中输入母语并手动翻译。
4. 未经用户确认，插件不改变网页输入框内容；确认后只填入译文，不自动发布。
5. 用户可以选择下载和删除语言包，状态在重启浏览器后保持。
6. 页面脚本错误、模型错误或权限不足时，不影响网页原有交互。
7. 单元测试覆盖语言包状态、消息协议、文本长度处理和输入框填充；端到端测试覆盖普通 HTML 测试页。

## 实施顺序

1. 验证 WASM 翻译引擎候选方案、许可证和 Chrome MV3 可行性。
2. 创建扩展骨架和最小权限配置。
3. 实现消息协议、语言包状态和模型缓存抽象。
4. 实现选中文本翻译闭环。
5. 实现通用输入框识别、回复面板和确认填入。
6. 实现语言包管理 UI 和下载校验。
7. 增加测试、打包和 Chrome 开发者模式安装说明。

## 未决技术风险

纯浏览器内置翻译的主要风险是开源 WASM 运行时和大型语言包的体积、内存占用、Chrome 扩展资源限制以及不同语言方向的覆盖率。因此实现第一步必须先做最小技术验证：在 MV3 扩展中加载一个真实开源运行时和一个语言方向，完成一次离线翻译后再扩大语言目录。若候选引擎无法满足许可证或浏览器限制，应暂停扩展功能扩展，先重新评估可行运行时，而不是偷偷改为云端翻译。
