# 端到端测试

分两层：

1. **自动化冒烟**（`npm run test:e2e`）：真 Chrome 加载 `dist/` 里的扩展，把
   popup 翻译、选中翻译、悬停翻译、回复助手四条主路径全跑一遍，并检查控制台没有
   CSP / ESM / WASM 报错。这层专门拦那些单元测试拦不住、只在真浏览器里才炸的问题。
2. **手工清单**（下面的检查项）：覆盖交互细节和离线能力。

## 自动化冒烟

```bash
npm run build
npm run test:e2e                    # 用已装好的语言包跑
npm run test:e2e -- --install en-zh # 缺包时先下载（约 40 MB）
CHROME_PATH=/path/to/chrome npm run test:e2e
```

默认有头模式（Chrome 老版 headless 不支持扩展）。浏览器 profile 固定在
`tests/e2e/.chrome-profile/`，语言包缓存在里面，**换 profile 就得重新下载**。
缺 playwright-core 或 Chrome 时脚本会直接告诉你怎么装，不会静默失败。

## 手工验证

覆盖设计文档验收标准里的第 1–6 条。

### 准备

1. `npm run build`
2. Chrome 打开 `chrome://extensions`，开启「开发者模式」
3. 「加载已解压的扩展程序」→ 选择 `dist/chrome-local-translator`
4. 打开本目录下的 `test-page.html`（双击即可，file:// 也能用）
5. 首次翻译会下载语言包，请先联网

## 检查清单

### 选中文本翻译

- [ ] 选中英文段落，出现「翻译选中」按钮，点击后弹出结果卡片
- [ ] 卡片里**不需要选语言**：上面是原文，语言条显示「自动检测 · 英语 → 中文（简体）」，
      下面是译文
- [ ] 译文出现后可点击「复制译文」
- [ ] 手动把目标语言改成「日语」，译文自动重新翻译
- [ ] 点语言条上的 ⇄，「自动检测 → 中文」变成「中文 → 英语」
- [ ] 选中日文段落，语言条自动显示「自动检测 · 日语」
- [ ] 按 Esc 或点 × 关闭卡片
- [ ] 关闭浏览器再打开同一页面（不联网），仍能翻译同一方向 → 验证离线能力

### 悬停翻译（读）

- [ ] popup 里打开「悬停翻译（读网页）」开关，关闭 popup 后回到页面
- [ ] 页面右下角出现「双语对照」悬浮按钮
- [ ] 鼠标停在英文段落上，段落右上角出现圆形「译」按钮
- [ ] 点击「译」，段落下方插入译文，样式不受网页影响
- [ ] 点「显示原文」切回原文，按钮变成「显示译文」
- [ ] 再点一次「译」，译文收起（不会重复翻译）
- [ ] 中文段落不出现按钮
- [ ] 输入框（textarea / contenteditable）内不出现按钮
- [ ] 关闭开关后按钮不再出现

### 整页双语对照（自动）

- [ ] 打开英文测试页，**什么都不点**，译文自动逐段出现在每段原文下面
- [ ] 首屏段落先出译文，往下滚动时后续段落继续跟上（视口驱动）
- [ ] 中文测试页不会自动翻译
- [ ] 语言包没装好时不会自动开始（不会偷偷下载）
- [ ] popup 里关掉「整页双语对照」后不再自动翻译

### 悬浮按钮（手动）

- [ ] 页面右下角常驻「双语对照」悬浮按钮（不依赖悬停开关）
- [ ] 点击右下角「双语对照」，按钮变为「翻译中 N/M · 点击停止」，逐段出译文
- [ ] 每个非中文段落下方自动插入中文译文（类似沉浸式翻译），中文段不动
- [ ] 译文节点里能看到原文（默认收起 3 行，点击展开），失败时原文也在
- [ ] 中英混排页面（如导航带中文的英文站）正常翻译，不报「源语言和目标语言相同」
- [ ] 引用块、列表项只翻叶子段落，不会嵌套翻两遍
- [ ] 翻译期间再点一下可停止，按钮变「继续翻译」
- [ ] 完成后按钮变「收起译文」，点击收起全部；再点恢复，不重新请求翻译
- [ ] 关闭悬停翻译开关，悬浮按钮消失、整页翻译停止

### 长文本分段

- [ ] 整段选中「长文本分段」区域的英文并翻译
- [ ] 状态栏提示「已分 N 段翻译完成」
- [ ] 译文包含段落**最后一句**的内容（不是被截断的前半段）

### 回复翻译与确认填入

- [ ] 点击评论框（textarea），出现「翻译回复」按钮
- [ ] 面板里输入中文草稿，语言条默认显示「自动检测 · 中文 → 英语」，不用手动选
- [ ] 点「生成译文」
- [ ] 确认「填入输入框」按钮在译文出现前是禁用的
- [ ] 点「填入输入框」后：
  - [ ] 评论框内容被替换成英文译文
  - [ ] 「框架镜像值」同步更新 → 说明框架能感知到变化
  - [ ] **页面没有发生任何提交或跳转**
- [ ] 对 `input[type=text]` 和 `contenteditable` 重复以上步骤
- [ ] 绑定输入框后把该输入框从 DOM 里移除（在控制台执行
      `document.getElementById('comment').remove()`），点「填入输入框」应提示输入框失效，
      而不是静默失败

### 不应触发的场景

- [ ] 聚焦密码框时不出现「翻译回复」按钮
- [ ] 整个流程中没有自动翻译整页内容
- [ ] 全程没有自动点击发送/提交按钮

### 语言包管理

- [ ] 右键扩展图标 → 选项，打开语言包管理
- [ ] 「常用组合」里显示「日语 → 中文」，并注明需要 2 个语言包
- [ ] 点击下载，进度条与状态文字实时更新
- [ ] 下载完成后状态变为「已就绪，可离线使用」
- [ ] 搜索框输入「韩」能过滤出韩语相关方向
- [ ] 删除一个已下载的语言包后，其他方向仍可用
- [ ] 重启浏览器后已安装的语言包状态保持

### 错误处理

- [ ] 断网后翻译一个新方向，应提示下载失败，而不是卡住
- [ ] 在 `chrome://` 开头的页面上使用扩展不应报错
